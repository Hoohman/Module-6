# Сетевое взаимодействие сервисов

Два сервиса, взаимодействующих по TCP:

- **NetworkLogFilter** (отправитель) — фильтрует IPv4-адреса и отправляет результаты по сети.
- **receiver** (приёмник) — принимает JSON-сообщения и выводит их в консоль.

## Требования

- CMake **3.30+**.
- Компилятор и стандартная библиотека с поддержкой C++20, корутин и `std::format` для времени.
- Boost **1.86+**: заголовки Asio и UUID, собранная библиотека Boost.JSON для выбранного компилятора и архитектуры.
- Make, Ninja или MSBuild — в зависимости от генератора CMake. Ninja необязателен.

## Сборка

Из корня проекта:

```bash
cmake -S . -B build
cmake --build build
```

Для выбора Ninja добавьте `-G Ninja` к первой команде, используя отдельный каталог сборки, например `-B build-ninja`.
Если Boost не найден, добавьте к первой команде `-DCMAKE_PREFIX_PATH="/path/to/boost-install"`, указав каталог его установки.

## Запуск

В двух терминалах из корня проекта: сначала приёмник, затем отправитель. Отправитель подключается к `127.0.0.1:30303`.

| Окружение | Терминал 1 — приёмник | Терминал 2 — отправитель |
| --- | --- | --- |
| Linux, Make/Ninja | `./build/receiver_service/receiver` | `./build/NetworkLogFilter/NetworkLogFilter` |
| Windows PowerShell, Ninja/MinGW Makefiles | `.\build\receiver_service\receiver.exe` | `.\build\NetworkLogFilter\NetworkLogFilter.exe` |
| Windows PowerShell, Visual Studio (Debug) | `.\build\receiver_service\Debug\receiver.exe` | `.\build\NetworkLogFilter\Debug\NetworkLogFilter.exe` |

Visual Studio по умолчанию собирает Debug. Для Release выполните `cmake --build build --config Release` и замените `Debug` на `Release` в путях запуска.
Если выбран другой каталог сборки, замените `build` в командах сборки и запуска.

## Демонстрация

Отправитель обрабатывает встроенный набор строк и передаёт 6 сообщений. Приёмник выводит каждое новое сообщение с префиксом `Received:`, например:

```text
Received: {"message_id":"8f739f04-bc4b-47a6-8474-d02dcbd42dd3","source_service":"ipv4_filter","timestamp_utc":"2026-10-22 12:00:00","payload":"192.168.0.5 - GET /"}
```

UUID и время UTC меняются при запуске. Каждый JSON заканчивается `\n`; приёмник отвечает ACK с тем же `message_id`. После подтверждения всех сообщений отправитель завершается с кодом 0.

## Обработка ошибок

- **Приёмник недоступен при запуске** — 3 попытки подключения с паузой 1,5 с; затем локальный вывод результатов и код завершения 1. Для демонстрации запустите отправитель без приёмника.
- **Ошибка доставки или ACK** — до 3 попыток одного сообщения с неизменным ID и паузой 1,5 с. Подключение, запись и чтение ACK имеют отдельные тайм-ауты по 5 с. После исчерпания попыток отправитель завершается с кодом 1.
- **Некорректное сообщение** — приёмник выводит ошибку и пропускает сообщение. Лимит кадра — 1024 байта, включая `\n`; тайм-аут чтения — 10 с. При превышении лимита или тайм-ауте соединение закрывается.
- **Повторы** — приёмник хранит последние 1000 обработанных ID в общем кэше и повторно отправляет ACK без повторного вывода. После вытеснения ID или перезапуска приёмника эта гарантия теряется.
