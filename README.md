# Сетевое взаимодействие сервисов

Два сервиса, взаимодействующих по TCP:

- **NetworkLogFilter** (отправитель) — фильтрует IPv4-адреса и отправляет результаты по сети.
- **receiver** (приёмник) — проверяет JSON-сообщения, сохраняет их в PostgreSQL и подтверждает обработку через ACK.

## Запуск через Docker Compose

На Windows, Linux и macOS достаточно Docker с Compose и поддержкой Linux-контейнеров. Образ собирает оба сервиса вместе с нужными C++-зависимостями.

Локальный тестовый пароль задан в `x-db-password` в [compose.yaml](compose.yaml). Compose передаёт одно значение PostgreSQL и приёмнику. Если том уже был инициализирован с другим паролем, укажите в `x-db-password` текущий пароль пользователя `appuser`. Изменение значения в Compose не меняет пароль в существующей БД.

Из корня проекта выполните команды:

```bash
docker compose up --build -d --wait db receiver
docker compose run --rm --no-deps sender
docker compose logs receiver
docker compose exec db psql -U appuser -d appdb -c "SELECT source_service, count(*) FROM messages GROUP BY source_service;"
```

Первая команда ждёт готовности БД и приёмника. Флаг `--no-deps` запускает только отправитель и оставляет работающие контейнеры как есть.

Отправитель передаёт 6 сообщений и запрашивает статистику. Пример вывода отправителя:

```text
Starting IPv4 Filter Service...
Successfully connected (receiver:30303)
```

После первого прогона на пустой БД в журнале приёмника будет такой вывод:

```text
[DB] Stored message id=8f739f04-bc4b-47a6-8474-d02dcbd42dd3
Total messages: 6
Source: ipv4_filter| Messages: 6
```

Периодические строки `Client disconnected cleanly.` могут появляться из-за TCP-проверки готовности приёмника.

`docker compose down` останавливает окружение и сохраняет данные в именованном томе `pgdata`. После повторного запуска БД и приёмника можно проверить сохранность записей тем же запросом `psql`. Если порт PostgreSQL на хосте занят, задайте `POSTGRES_HOST_PORT=5433` в окружении терминала перед запуском Compose (`$env:POSTGRES_HOST_PORT = '5433'` в PowerShell или `export POSTGRES_HOST_PORT=5433` в Bash). Внутри Compose приёмник подключается к `db:5432`.

## Хранение сообщений

При небольшом объёме сообщений и одном процессе записи подошла бы [SQLite](https://www.sqlite.org/whentouse.html). Она встраивается в приёмник, поддерживает [ACID-транзакции](https://www.sqlite.org/transactional.html) и имеет [C API для работы из C++](https://www.sqlite.org/cintro.html). PostgreSQL требует отдельного серверного процесса, но поддерживает [конкурентные транзакции](https://www.postgresql.org/docs/18/mvcc-intro.html). Он выбран для практики с клиент-серверной БД, транзакциями и C++-клиентом [libpqxx](https://github.com/jtv/libpqxx). Compose автоматизирует запуск сервера.

Приёмник выполняет [schema.sql](receiver_service/schema.sql) при запуске. Таблица `messages` хранит источник, время отправки и строковый `payload`, а также числовой первичный ключ `id`, время приёма `received_at` и уникальный сетевой UUID `message_id`.

Сообщения передаются как JSON с разделителем `\n`. ACK содержит исходный `message_id` и отправляется после фиксации записи. Повтор с тем же UUID получает ACK без новой строки. Команда `control/stats` выводит число сохранённых сообщений и разбивку по источникам, сама команда в БД не сохраняется.

## Обработка ошибок

- **Приёмник недоступен при запуске** — 3 попытки подключения с паузой 1,5 с; затем локальный вывод результатов и код завершения 1. Для демонстрации запустите отправитель без приёмника.
- **Ошибка доставки или ACK** — до 3 попыток одного сообщения с неизменным ID и паузой 1,5 с. Подключение, запись и чтение ACK имеют отдельные тайм-ауты по 5 с. После исчерпания попыток отправитель завершается с кодом 1.
- **Некорректное сообщение** — приёмник выводит ошибку и пропускает сообщение. Лимит кадра — 1024 байта, включая `\n`; тайм-аут чтения — 10 с. При превышении лимита или тайм-ауте соединение закрывается.
- **Ошибка БД** — при недоступной базе приёмник завершает запуск с ошибкой. При ошибке вставки он пишет сообщение в журнал, закрывает текущее соединение без ACK и продолжает слушать порт. После потери подключения из-за перезапуска PostgreSQL дождитесь готовности `db` и выполните `docker compose restart receiver`.
